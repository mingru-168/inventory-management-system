# 生产流程优化设计方案

## 1. 概述

### 1.1 项目背景
优化库存管理系统中的生产流程，实现销售订单审核后系统自动匹配库存配货，以及无库存时自动进入生产流程的完整闭环。

### 1.2 目标
- 有库存订单：审核通过后系统自动配货，无需手动操作
- 无库存订单：自动进入生产流程，完工入库后自动配货
- 工序流程：支持自定义配置、派工、完工确认
- 全流程状态清晰，操作简便

---

## 2. 业务流程

### 2.1 流程A：有库存配货

```
销售订单 → 审核（系统自动匹配库存并配货） → 锁定库存 → 发货 → 完成
```

**详细步骤**：
1. 创建销售订单（选择客户、产品、数量）
2. 审核订单时，系统自动检查产品库存
3. 如有库存，系统自动配货并锁定库存
4. 订单状态更新为"待发货"
5. 执行发货操作
6. 订单完成

### 2.2 流程B：无库存生产

```
销售订单 → 审核（系统检测无库存） → 安排生产 → 创建计划订单 → 配置工序 
→ 派工 → 工序1完工确认 → ... → 入库工序确认 → 自动配货 → 发货 → 完成
```

**详细步骤**：
1. 创建销售订单（选择客户、产品、数量）
2. 审核订单时，系统自动检查产品库存
3. 如无库存，订单状态更新为"待生产"
4. 点击"安排生产"，创建计划订单
5. 配置工序列表（最后一道固定为"入库"）
6. 为每道工序指定执行人
7. 执行人在生产看板中确认各工序完工
8. 入库工序确认后，自动触发配货
9. 订单状态更新为"待发货"
10. 执行发货操作
11. 订单完成

## 3. 数据结构

### 3.1 计划订单 (PlanOrder)

```javascript
{
  id: string,              // 唯一标识
  orderId: string,         // 关联的销售订单ID
  productId: string,        // 产品ID
  productName: string,      // 产品名称
  quantity: number,         // 生产数量
  status: string,           // pending | in_progress | completed
  createdAt: string,        // 创建时间
  updatedAt: string         // 更新时间
}
```

### 3.2 工序 (Process)

```javascript
{
  id: string,              // 唯一标识
  planOrderId: string,      // 关联的计划订单ID
  name: string,             // 工序名称
  sequence: number,          // 顺序（1, 2, 3...）
  status: string,           // pending | in_progress | completed
  assignee: string,         // 执行人/班组
  completedAt: string,      // 完成时间
  createdAt: string        // 创建时间
}
```

### 3.3 销售订单状态流转

| 状态 | 描述 | 触发条件 |
|------|------|----------|
| pending | 待审核 | 订单创建 |
| approved | 已审核-待配货/待生产 | 审核通过，有库存 |
| in_production | 已审核-生产中 | 审核通过，无库存 |
| allocated | 已配货 | 配货完成 |
| ready_to_ship | 待发货 | 配货完成或有库存审核通过 |
| shipped | 已发货 | 发货操作 |
| completed | 已完成 | 确认收货 |

## 4. 功能模块

### 4.1 订单审核（自动配货）

**功能**：审核销售订单时，系统自动检查库存并配货

**逻辑**：
1. 用户点击"审核订单"
2. 系统查询产品库存
3. 如库存 >= 订单数量：
   - 自动创建配货记录
   - 锁定对应库存
   - 更新订单状态为 "allocated"
4. 如库存 < 订单数量：
   - 更新订单状态为 "in_production"
   - 显示"库存不足，需安排生产"提示

**API**：
- `POST /api/sales-orders/:id/approve`
  - 请求体：`{ forceApprove: boolean }`
  - 响应：`{ success: boolean, order: Order, allocation?: Allocation }`

### 4.2 安排生产

**功能**：将待生产的销售订单安排生产，创建计划订单

**逻辑**：
1. 用户点击"安排生产"按钮
2. 系统创建计划订单
3. 跳转到工序配置页面

**API**：
- `POST /api/plan-orders`
  - 请求体：`{ orderId: string, productId: string, quantity: number }`
  - 响应：`{ planOrder: PlanOrder }`

### 4.3 配置工序

**功能**：为计划订单配置工序列表

**逻辑**：
1. 用户在计划订单详情页面配置工序
2. 每条工序包含：名称、顺序
3. 系统自动在最后添加"入库"工序（不可删除）
4. 保存后，计划订单状态更新为 "in_progress"

**API**：
- `PUT /api/plan-orders/:id/processes`
  - 请求体：`{ processes: [{ name: string, sequence: number }] }`
  - 响应：`{ success: boolean, processes: Process[] }`

### 4.4 派工

**功能**：为每道工序指定执行人

**逻辑**：
1. 用户选择工序，点击"派工"
2. 从人员列表中选择执行人
3. 保存派工信息

**API**：
- `PUT /api/processes/:id/assign`
  - 请求体：`{ assignee: string }`
  - 响应：`{ success: boolean, process: Process }`

### 4.5 生产看板

**功能**：显示所有待确认的工序，支持快速确认

**界面**：
- 独立页面/标签页
- 列表展示：工序名称、关联订单、执行人、状态、操作按钮
- 支持按状态筛选（待派工、待确认）
- 点击"确认完工"弹出确认框

**API**：
- `GET /api/processes?status=pending`
  - 响应：`{ processes: Process[] }`

### 4.6 工序完工确认

**功能**：确认工序完工，进入下一工序

**逻辑**：
1. 用户点击"确认完工"
2. 弹出确认对话框
3. 用户确认后：
   - 更新工序状态为 "completed"
   - 记录完成时间
   - 如为"入库"工序：
     - 创建入库记录
     - 增加库存
     - 自动触发配货
     - 更新计划订单状态为 "completed"
     - 更新销售订单状态为 "allocated"

**API**：
- `PUT /api/processes/:id/complete`
  - 响应：`{ success: boolean, process: Process, isLastProcess?: boolean }`

### 4.7 入库确认弹窗

**功能**：确认入库工序时，弹出确认框并显示入库信息

**弹窗内容**：
- 产品名称
- 入库数量
- 入库仓库
- 仓位
- 确认/取消按钮

### 4.8 自动配货

**功能**：入库完成后，自动为原销售订单配货

**逻辑**：
1. 入库工序确认完成后触发
2. 根据计划订单关联的销售订单ID查找原订单
3. 创建配货记录
4. 锁定对应库存
5. 更新销售订单状态为 "allocated"

## 8. 错误处理

### 8.1 审核订单失败
- 库存不足：提示用户选择"安排生产"或"取消订单"
- 订单状态不对：提示"订单状态不允许审核"

### 8.2 工序完工确认失败
- 上一工序未完成：提示"请先完成上一工序"
- 工序状态不对：提示"该工序状态不允许确认"

### 8.3 入库失败
- 库存锁定失败：提示"库存锁定失败，请重试"
- 配货失败：提示"配货失败，请手动处理"

## 10. 附录

### 10.1 术语说明

| 术语 | 说明 |
|------|------|
| 计划订单 | 根据销售订单创建的生产计划 |
| 工序 | 生产过程中的单个作业步骤 |
| 派工 | 将工序分配给执行人 |
| 配货 | 将库存分配给订单 |

### 10.2 状态说明

**计划订单状态**：
- pending：待配置工序
- in_progress：生产中
- completed：已完成

**工序状态**：
- pending：待派工
- in_progress：进行中
- completed：已完成
