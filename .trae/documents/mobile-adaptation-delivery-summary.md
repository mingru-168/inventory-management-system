## 一、交付背景

系统为桌面优先设计（Tailwind 断点 + hover 下拉导航），手机端体验不佳：导航依赖 hover、宽表格溢出屏幕、弹窗超宽。批次6 在**不动桌面端行为**的前提下，为 ≤768px 视口补全套移动端体验。

## 二、功能清单

| 功能        | 说明                                             | 文件         |
| --------- | ---------------------------------------------- | ---------- |
| 汉堡抽屉导航    | 左上角汉堡按钮，左侧滑出 240px 侧边栏 + 半透明遮罩，点击遮罩/外部关闭       | index.html |
| 点击式下拉菜单   | 移动端下拉标题点击展开/收起（内联展开，覆盖桌面 hover/fixed），跨断点自动复位  | index.html |
| Header 精简 | ≤768px 隐藏副标题/用户名/邮箱文字，仅保留图标                    | index.html |
| 表格横向滚动    | 白卡片自身成为滚动容器，表格 `min-width:max-content`，页面不横向溢出 | index.html |
| 弹窗窄屏封顶    | `max-width: calc(100vw - 32px)`，防窄屏溢出          | index.html |
| 导航收口      | `navigateTo()` 顶部统一关闭抽屉，所有导航入口生效               | app.js     |

所有 CSS 规则均包裹在 `@media screen and (max-width: 768px)` 内，桌面（>768px）零变化。

## 三、测试与验证

### 3.1 测试方法

浏览器代理的视口被锁定（无法调到 375px），改用**确定性方案**：Chrome 无头 + puppeteer-core 精确设置 375px 视口，注入有效登录态，JS 实测渲染值。

### 3.2 发现并修复的两个 Bug（提交 `7f57760`）

| Bug    | 现象                       | 根因                                                                              | 修复                                   |
| ------ | ------------------------ | ------------------------------------------------------------------------------- | ------------------------------------ |
| 抽屉宽度错误 | 抽屉实际 176px 而非设计 240px    | Tailwind `.w-44`（特异性 0,1,0）覆盖 media query 内 `aside` 元素选择器（0,0,1）的 `width:240px` | 补 `!important`                       |
| 下拉无法收起 | 收起后约 100+ 子菜单项仍常驻堆叠，抽屉极长 | `.sidebar-dropdown-content-wrapper` 无隐藏规则（桌面本就常驻显示）                             | 未 `open` 时 `display:none`，`open` 时显示 |

### 3.3 确定性验证结果（375px）
